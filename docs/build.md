# Сборка

Основной проект — **smart_exam.cbp** в корне. Открыть в Code::Blocks,
выбрать GNU GCC Compiler, цель Debug, нажать F9 (Build and Run).
Путь SFML: `C:/SFML-2.5.1`; если он другой, изменить каталоги Compiler и Linker
в Build options. Рабочий каталог — корень репозитория, где находятся `db/` и `data/`.

Как в остальных проектах, SFML подключена статически: Debug использует библиотеки
`sfml-*-s-d`, Release — `sfml-*-s`. Дополнительные библиотеки:
`opengl32`, `freetype`, `winmm`, `gdi32`, `comdlg32`.
Исходники SQLite собираются как C. Флаг C++11 для них может вызвать предупреждение GCC.
Шрифт Segoe UI или Arial читается из системной папки Windows/Fonts.
Для заголовков и формул используется Georgia, при её отсутствии — основной шрифт.

В `project/`: `smart_exam.cbp`, `tests.cbp` (ядро), `ui_tests.cbp` (интерфейс).
Основной файл в корне и копия в `project/` обновляются одной командой ниже.

Дополнительный путь проверки из корня: `python tools/build.py --mode Debug --smoke`,
затем `python tools/build.py --mode Release`. Путь компилятора задаётся `--compiler`,
путь библиотеки — `--sfml`. Python нужен только для вспомогательной сборки, не для приложения.
После добавления исходников обновить проекты командой `python tools/update_projects.py`.

Локально обнаружены TDM GCC 5.1.0 (mingw32) и SFML 2.5.1 (i386).
Это 32-битный комплект; успешная сборка им не подтверждает целевую Windows x64.
Проверка согласованного x64-комплекта и сборка на другом компьютере остаются отдельными пунктами приёмки.

Параметр `--smoke` открывает окно и закрывает его через секунду для проверки запуска.

После сборки: `run.bat demo` — консольный сценарий, `run.bat tests` — проверки,
`run.bat widgets` — демонстрация элементов, `run.bat` — приложение.
Локальные данные: `data/smart_exam.db`; база создаётся при первом запуске.
