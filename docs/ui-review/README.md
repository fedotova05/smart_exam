## Текущая версия

Выполнен `git fetch origin --prune`. Исходная рабочая копия `5f4ac6b` отставала от main на слияние ветки и правку README. Различий в исходниках приложения не было. Рабочая ветка обновлена fast-forward до `971876e`. SSH подтвердил пользователя `fedotova05`.

- C++11, SFML 2.5.1, SQLite из `third_party/sqlite`.
- Code::Blocks, GNU GCC; дополнительная сборка — `tools/build.py`.
- Статическая SFML, комплект Win32. Переход на другую технологию не требуется.
- Segoe UI/Arial для текста, Georgia для заголовков и формул; системные шрифты Windows.
- Цвета вынесены в `Theme.h`; формулы, графики и изображения имеют собственные виджеты.
- Данные — `data/smart_exam.db`. Черновики ответов, история попыток, результаты, условия занятия и профили уже сохраняются.
- `SchoolService` отделяет экраны от предметных операций; экраны вызывают его через `AppContext`.

## Карта экранов

| Роль / раздел | Доступные действия и переходы |
|---|---|
| Вход | Выбор роли → профиль ученика / пароль учителя; отдельный вход в демонстрацию |
| Ученик: моё занятие | Продолжение сохранённого занятия или выбор тем и режима |
| Выбор темы | Тренировка / проверка знаний → темы и навыки → количество → запуск |
| Решение | Условие → часть задания → текст / график / шаги → проверка → завершение задания → следующее / итоги |
| Разбор ошибки | Повтор ответа или отдельные упражнения на связанные навыки с возвратом |
| Прогресс | Оценки навыков, количество наблюдений, подсказки → карта связей / история |
| История | Попытки → ответы и баллы → тренировка по ошибкам |
| Учитель: кабинет | Выбор ученика → подготовка занятия, ручная проверка, история, профили |
| Банк | Поиск → черновик → части, формулы, навыки и правила ответа → предпросмотр → публикация |
| Сборка занятия | Банк / генератор / подбор → состав → проверка → условия и шаблоны → назначение |
| Ручная проверка | Очередь и фильтры → условие, ответ, комментарий → вердикт; экспорт CSV |
| Пакеты | JSON → чтение → сопоставление навыков → импорт и отчёт; экспорт |

Проверка решений и управление учениками вынесены в отдельные пункты меню и маршруты. Их формы используют существующие операции кабинета.

## Проблемы исходной версии

| Проблема | Основание | Что изменить |
|---|---|---|
| Просмотр темы одновременно выбирает или снимает все её навыки | `TrainingSetupScreen.cpp`: `topicsList->onChange` меняет `selected`; снимок `training-setup.png` | Разделить открытие темы и флажок выбора. Стрелки перемещают фокус, Space меняет выбор |
| Стрелки в списке могут менять данные | `ListBox::handle` вызывает `onChange` на Up/Down, а выбор темы использует этот callback как команду | Отдельные события выделения и активации |
| «Проверить» и «Завершить задание» расположены далеко друг от друга | `LessonScreen.cpp`, снимки решения | Один блок действий: проверка, видимый результат, затем завершение; сохранить возможность закончить без ответа через явное подтверждение |
| Сообщение проверки находится внизу окна, а не у ответа | `Screen::draw`: status на y=634; `LessonScreen::send` записывает туда результат | Обратная связь рядом с полем, отдельная строка для общих ошибок |
| Enter в ответе и пароле ничего не отправляет | `TextField` поддерживает `onEnter`, но эти экраны его не назначают | Привязать Enter к основному действию с защитой от повторной отправки |
| Tab не достигает верхней навигации | `Screen::handle` обходит только widgets; навигация хранится отдельно в `App` | Общий порядок фокуса для навигации и содержимого |
| После `refresh()` фокус сбрасывается | `Screen::clear` устанавливает focus=-1 и уничтожает виджеты | Сохранять смысловой идентификатор фокуса и выделения |
| Настройки показывают неприменимые параметры | `BankScreen.cpp`, снимок `answer-settings.png`: график, округление, линейные шаги и варианты на одной форме | Показывать правила выбранного типа ответа; остальные параметры скрывать |
| Пользователь вводит внутренние коды | В редакторе — коды навыков; варианты через `\|`; ответ выбора — номера через `;` | Выбор навыков по названиям, отдельные строки вариантов, флажки ответа с преобразованием в текущий формат |
| Узкие списки сокращают названия без раскрытия | `ListBox::draw` использует `shorten`; тема обрезана на `training-setup.png` | Перенос в 2 строки или полное название рядом с выбранной строкой |
| Размер окна меняет масштаб, но не компоновку | `App::resize`: логическое поле 1200×800, уменьшение до 1024×720, максимум масштаба 1 | Пересчитывать размеры областей; текст не уменьшать вместе со всем экраном |

Не утверждаем без пользовательской проверки: что ученики действительно путают баллы и освоение, что ручная проверка слишком глубоко спрятана, что текущая палитра им не нравится. Это гипотезы. У приложения уже есть объяснения баллов, пустые состояния, диалоги, прокрутка списков и сохранение черновиков — их не нужно создавать заново.

## Что сохраняем

- Проверку ответов, генераторы, адаптивный подбор, SQLite, восстановление, правила времени и отложенного показа оценок.
- `FormulaView`, `GraphView`, `ImageView`, сохранение черновиков и фоновые операции с отменой.
- Основу кнопок, полей и панелей. Улучшаем размер, фокус, сообщения и компонование.
- Разделение ученика и учителя, черновика и опубликованной версии.

Заменяем перегруженную ручную компоновку экранов и строковые обозначения выбора. Достаточен небольшой слой размещения областей и управления фокусом; переписывание предметного слоя не обосновано.

Незавершённое: загрузка из ФИПИ прямо помечена недоступной. Настоящие доступные пакеты — локальный JSON. Полная поддержка скринридера не подтверждена: отрисовка SFML сама по себе не создаёт системное дерево доступности. Новые зависимости не предлагаются.

## Референсы

Изучены официальные руководства и доступные изображения. Чужие изображения и оформление в приложение не переносятся.

### 1. Moodle Quiz

[Прохождение и проверка теста](https://docs.moodle.org/503/en/Using_Quiz).
Изучены переходы между вопросами, сводка перед отправкой, отложенная обратная связь, фильтры учителя и пересмотр оценки. Принцип: различать «ответ сохранён», «вопрос завершён» и «проверен». Предварительная сводка помогает заметить пропущенные ответы. Для SmartExam: текстовые состояния частей задания, подтверждение завершения с количеством неотправленных частей, очередь ручной проверки. Реализуется существующими сервисами и диалогом SFML. Свободный переход к любому вопросу и флажки возврата не переносим: текущий движок выдаёт задания последовательно. Живой курс с учётной записью не проверялся; выводы основаны на документации.

### 2. Desmos

[Руководство калькулятора](https://help.desmos.com/hc/en-us/articles/202529279-Desmos-Graphing-Calculator-User-Guide), [клавиатура](https://www.desmos.com/shortcuts).
Изучены изображение рабочей области, список выражений, управление графиком, клавиатура символов и доступ к настройкам. Поле и его результат расположены рядом; дополнительные инструменты раскрываются по необходимости. Это снижает перемещение взгляда. В SmartExam оставляем текущие `FormulaView` и `GraphView`, ставим ввод рядом с предпросмотром, показываем только нужные символы, подписываем масштаб и сброс вида. Не переносим универсальный вычислитель, аккаунты, публикацию и сложные жесты без подписей. Математическая клавиатура должна вставлять синтаксис существующего парсера, не имитировать новый редактор формул.

### 3. GeoGebra

[Алгебраическое представление](https://geogebra.github.io/docs/manual/en/Algebra_View/), [ввод и история](https://geogebra.github.io/docs/manual/en/Input_Bar/).
Изучены снимок настольной компоновки, связанные алгебраическая и графическая области, редактирование объекта, история ввода. Полезен принцип «выбранный объект → его параметры → немедленный результат». Для банка заданий: список частей слева, редактор выбранной части в центре, предпросмотр рядом; для графических ответов — подписанные коэффициенты. В SFML это три ограниченные области с независимой прокруткой и единым выбранным partId. Не переносим весь набор геометрических инструментов, переставляемые панели и язык команд. Доступный снимок мал, поэтому по нему оценивалась только компоновка, а поведение — по руководству.

### 4. Anki

[Учебная сессия](https://docs.ankiweb.net/manual/studying).
Изучены выбор набора, обзор перед началом, состояние вопроса, показ ответа, смена действий и возврат к набору. Полезен один главный шаг за раз: сначала решить, затем увидеть результат и продолжить. Это особенно подходит ученику, которому мешают постоянные боковые панели. В SFML: состояние блока ответа `editing / checked / finished`, один акцентный переход, подсказка по запросу. Не переносим самооценку вместо автоматической проверки, алгоритм повторений и автоматическое продвижение. Изображение обзора через публичный источник вернуло 403; визуальные детали этого изображения не использовались.

## Три направления

Во всех макетах одинаковые данные: Мария, тренировка «Квадратные уравнения», задание 2 из 5, `x² − 5x + 6 = 0`, одна часть, 1 балл. Это демонстрационный сценарий. Проверка макета работает только для примера с корнями 2 и 3; база приложения не подключена.

| Направление | Экраны и основной путь | Стиль и ограничения | Объём |
|---|---|---|---|
| A. Фокус | Кабинет → выбор темы → отдельный спокойный экран решения → результат → продолжение. Условие, ответ и результат по одной вертикали; помощь раскрывается рядом | Светлая тёплая поверхность, крупная формула, один основной акцент. Меньше отвлечений; история требует раскрытия | Средний: App, LessonScreen, общие состояния и фокус; затем остальные экраны |
| B. Рабочее место | Постоянные разделы слева, задача в центре, части и история справа; переходы доступны всё время | Строгая сетка, выше плотность. Хорошо для учителя и составных заданий; теснее при 1024×720 | Средний/высокий: общая оболочка, размещение областей, прокрутка панелей |
| C. По этапам | Условие → ввод → результат, с явным возвратом. Аналогично мастер настройки и публикации | Самая низкая плотность на каждом шаге. Понятный порядок, но больше переходов. Это этапы интерфейса, а не проверка математических преобразований | Высокий: состояния экранов, сохранение ввода между этапами, возвраты |

Рекомендация: A для решения учеником; для кабинета учителя — организация списка и редактора из B. Палитра, кнопки и сообщения остаются едиными. Скрытие общей навигации во время решения и новое расположение действий требуют выбора пользователя.

## Проверка исходной версии

- `bin/Debug/smart_exam.exe --capture`: успешно, отдельная база в памяти. Проверены полученные снимки входа, решения, выбора тем, кабинета, параметров ответа, прогресса и разных размеров окна.
- Тесты покрывают Unicode, курсор, фокус, диалог, прокрутку, формулы, график и сценарий ученика. Это не полноценное ручное прохождение каждого экрана.
- Не проверены на этом этапе: Release заново, другой компьютер, комплект x64, все длинные и пограничные значения, работа со скринридером.
- Рабочая база не использовалась для снимков. Исходники приложения не менялись.
- В макетах проверены переключение A/B/C, пустой и неверный ответ, правильные корни в обоих порядках, отправка Enter, завершение и повтор примера. Переходы в другие разделы и следующее задание обозначают структуру, но не подключены. Пауза и история действуют только в памяти макета.

## Исходный порядок внедрения

Сначала реализовать один законченный сценарий: открыть занятие → ввести ответ → увидеть ошибку/успех → исправить или запросить помощь → завершить → перейти дальше. Показать реальные снимки и получить обратную связь. Затем применить выбранный подход к темам, истории, прогрессу и кабинету учителя.

Контрольные состояния: пустой ответ, некорректный синтаксис, ошибка вычисления, успех, отложенная проверка, обязательные шаги, составное задание, длинное условие, рисунок и график. Проверить Tab/Shift+Tab/Enter/Esc, сохранение фокуса и черновика, размеры 1024×720, 1200×800 и 1600×900. Правила подсказок, подсчёта навыков и времени не изменять.
